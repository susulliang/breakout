# Breakout 2D-to-3D Isometric Port Implementation Plan

**Goal:** Port the working shooter to a real, depth-tested 3D world with an orthographic isometric-style camera, preserving its controls, progression, weapons, healing, hit feedback, and stylized industrial identity.

**Architecture:** Keep the existing deterministic grid generation and flat, bounded gameplay state. Migrate rendering through an opt-in 3D backend, retain two-dimensional ground movement on the world XZ plane, and give projectiles, hit volumes, lights, and effects real world-space height. Temporary character billboards are a migration checkpoint, not the finished port: the final release must have geometric humanoids, four geometric weapons, geometric props, and proportionate detached 3D body parts.

**Tech stack:** Existing C++17, CMake >= 3.16, Raylib 5.0, desktop OpenGL 3.3/GLSL 330. No engine replacement, ECS, general physics engine, or mandatory external asset tool.

**Estimated time:** 8 milestones, approximately 6-10 engineering days plus visual tuning. Each milestone is decomposed into individually verifiable actions below. Camera/mesh scaffolding is relatively small; robust combat and full presentation parity are not five-minute features. Do not treat a compiling prototype as a completed port.

**Document status:** Implementation handoff only. Source audit performed on 2026-10-09 after the user confirmed the prototype works well. This document does not implement or verify any 3D behavior.

### Known Defects: Correct, Do Not Copy Blindly

1. Rendered tiles centered at integer positions disagree with floor-based collision intervals. Resolve once before constructing 3D boxes.
2. `LineOfSight` uses an endpoint-skipping condition that fails for horizontal/vertical lines; skip only the actual start/end cells.
3. Bullets hit walls in `CombatSystem` before enemies in `EnemySystem`, ignoring nearer enemies in the same frame.
4. Enemy impacts depend on array order rather than nearest geometric impact.
5. Body/head detection mixes Cartesian and pixel coordinates; visual projectile height is omitted from collision.
6. Exact overlapping enemies/player have zero-distance guards that leave unresolved overlaps/contact. Use a stable fallback separation direction.
7. Spawning checks points rather than actor footprints; corrected cell centers and clearance checks must avoid wall overlap.
8. Bullet allocation failure still spends ammo/cooldown; reserve a complete shot before spending ammo.
9. Light ranking compares tile positions with a pixel-space camera target. Replace with one-space selection.
10. `LightingSystem::Resize` has no current main-loop caller; end screens use a different/unwrapped scene path.
11. Shader id != 0 is not enough: Raylib5 can return its nonzero default shader after custom shader failure.
12. Escape is also Raylib's default close key; explicitly `SetExitKey(KEY_NULL)` if retaining Escape-to-menu.
13. Existing asset copy runs only after link; asset-only edits can leave packaged textures/shaders stale.

Record defect corrections separately from intended gameplay changes in verification notes.

## 3. Binding Design Decisions

### 3.1 Coordinate Convention

Use one world unit per tile. Ground position `(u,v)` remains `Vector2` and maps to `Vector3{u,height,v}`. World +Y is up. Do not call the ground coordinate `y` in new 3D code: use `gridY`/`v` or `z`.

Cell `(i,j)` occupies `[i,i+1) x [j,j+1)` and has center `(i+0.5,j+0.5)`. Its wall AABB is `{i,0,j}` to `{i+1,wallHeight,j+1}`. All floor models, wall meshes, tile picking, spawn/exit locations, enemy/pickup candidates, prop anchors, and room-light centers follow this convention.

Keep map indices, room rectangles, corridor carving, and RNG seeds unchanged. Shift chosen integer object locations by +0.5, but do not shift grid indices or index a center by rounding. Room center used for carving can remain integral until carving completes; export geometric center separately or convert all consumers consistently afterward.

Movement requires the actor footprint to remain on walkable floor. Use `TileAt(...) != kTileFloor` as movement-blocking for void/out-of-map/wall; use actual wall AABBs for projectile obstruction. Do not make all void into infinite bullet-blocking volumes. Update bounds to footprint-aware limits under the new convention, not `mapWidth-1` point clamps.

### 3.2 Camera

Use Raylib `Camera3D` with `CAMERA_ORTHOGRAPHIC`, yaw 45 degrees, elevation 30 degrees. The existing 2:1 diamond is dimetric, commonly called isometric; mathematical true-isometric elevation 35.264 degrees does NOT reproduce this diamond. Preserve the recognizable view, not the terminology.

Camera direction from target to eye is proportional to `(1,0.8164966,1)`. Normalize and multiply by an eye distance such as 30. Distance changes clipping/picking origin, not orthographic magnification.

Starting calibration:

- `pixelsPerWorldUnit = 45.254834` for 64x32 projected tiles.
- `camera.fovy = viewportHeight / pixelsPerWorldUnit`; orthographic fovy is visible vertical world span, NOT an angle.
- At 720 pixels high, fovy is about 15.9099.
- World X and Z tile vectors project to `(32,16)` and `(-32,16)`.
- World height projects upward by `pixelsPerWorldUnit*cos(30deg) = 39.191836 pixels/unit`.
- Original 32-pixel wall extrusion corresponds to height 0.816497 units.
- Begin with visible wall height 0.816497. Use this SAME height for geometry and projectile AABBs. If the user later wants tall walls, raise both together and enable the foreground readability policy below.
- Character feet at height 0; start actor height approximately 1.20 units and visible width approximately 0.40-0.50 units.
- Player framing remains horizontally centered and around 55% viewport height. Lift target above ground by `0.05*viewportHeight / (pixelsPerWorldUnit*cos(30deg))`, and move eye with it.
- Follow smoothing continues in world space; camera snapshot used for this frame's input is also the camera used for this frame's drawing. No additional camera recompute after aiming.
- Viewport resize recomputes fovy and framing, not yaw/elevation; one tile remains approximately 64x32 pixels at zoom 1.

Optional debug zoom adjusts pixelsPerWorldUnit within bounded limits. Do not add camera rotation until screen-direction movement and aiming tests cover it.

### 3.3 Movement

Preserve current screen movement speed, not a naive normalized XZ vector. Current inverse mapping is:

```cpp
// screenInput has first been normalized in screen space.
Vector2 groundVelocity{
    (screenInput.y + 0.5f * screenInput.x) * player.speed,
    (screenInput.y - 0.5f * screenInput.x) * player.speed
};
```

This gives equal visible speed for horizontal/vertical input at baseline projection, but different ground-space distances. Normalizing the result again would change prototype feel. This is intentional parity.

For a generalized orthographic camera, compute the 2x2 Jacobian of projected ground unit vectors, invert it, and multiply normalized screen input by `32*player.speed` pixels/second at zoom 1. Compensate debug zoom so input does not become slower/faster when zoom changes. Start with the fixed-camera formula above; keep a test validating the projected result.

Mouse aiming remains independent of movement. Use a continuous ground yaw rather than left/right-only mirrored facing for 3D models.

### 3.4 Mouse Picking And Aiming

One shared `AimResult` is computed once per update using `GetMouseRay(GetMousePosition(), camera3D)`. Raylib5 exposes `GetMouseRay`, not the newer renamed screen-ray API. Never construct an orthographic ray by subtracting cursor from camera position.

Candidate cursor hits:

1. Ray vs live enemy explicit head/body hit volumes.
2. Ray vs static wall boxes.
3. Ray vs floor plane `Y=0`, then tile bounds/walkability.

Choose nearest positive visible intersection, not pool order. An obscuring wall excludes target assistance behind it. Ignore cosmetic props, fragments, decals, and glows for picking.

When cursor hits enemy head/body, use that hit point as ballistic aim point. When cursor hits a wall, use the surface point. When cursor hits floor or misses the level, derive horizontal aim from the floor-plane intersection but place the aim point at muzzle height to retain readable default flat shots. Guard parallel/near-parallel rays, negative distance, and zero-length direction; retain last valid heading if no valid aim.

Ray-plane ground picking and target assistance are not damage. Actual damage occurs only when the projectile later intersects a hit volume. No cursor-selected instant kill or headshot flag baked into the bullet.

Important behavior correction: with physical geometry, head shots above a wall of height 0.816497 can pass over it. Do not create an invisible infinitely tall bullet wall just to duplicate the old 2D block. Test this explicitly. Ground movement/LOS stay wall-blocked, so this does not add enemy traversal. If this is undesirable, increase real wall height with matching presentation and obtain user approval for that gameplay/readability change.

### 3.5 Projectile/Hit Contract

Convert only `Bullet::pos`, `previousPos`, and `vel` to `Vector3`. Remove/stop using `aimScreen`. Ground actors remain `Vector2`.

- Start at a deterministic weapon muzzle transform, outside the player's collider, around height 0.75 units.
- Sweep the player/weapon-root to muzzle segment against walls before spawning. Clamp an obstructed muzzle to the near wall surface and resolve its wall impact, or reject the shot consistently; never spawn a projectile on the far side of a wall. Add a wall-adjacent long-weapon regression.
- Use the selected weapon's speed in world units/s; preserve damage/cadence/spread/ammo.
- Shotgun spread rotates the normalized direction about world Y, preserving five pellets and angular spacing. Guard degenerate pitch.
- No new gravity for default bullets during initial parity: slingshot aesthetic comes from pebble plus narrow tracer, not splash/glow blob.
- Sweep the entire frame segment and resolve the earliest wall/body/head/time-of-impact.
- Head and torso volumes are independent, in world units, derived from the same model part dimensions. Start head sphere center at height 1.03, radius 0.17; body AABB height range 0.08-0.85, half width 0.26. Tune broad-phase generous radius without turning every upper-body hit into headshot.
- Avoid a head fully enclosed by a giant body volume. Ties within epsilon choose head; a strictly nearer torso hit remains body.
- Use wall-box expansion by bullet radius for a conservative sweep. Sphere expansion is exact for projectile vs head. Expanded body boxes are conservative near corners; document and test tolerance.
- Compare normalized segment time `t in [0,1]` across ALL candidates. Equal wall/enemy time: wall wins to prevent through-wall hits.
- Broad-phase static candidates from segment XZ bounding cells; dynamic candidates from active enemy pool. Do not scan/render-triangle collide the entire level for every bullet.
- Spawn wall sparks at the real hit point and orient outward to wall normal.
- Call `EnemySystem::ApplyDamage(game,index,damage,hitPosition,shotDirection,headshot)` once after a hit. That function owns HP/count/feedback/stagger/death. Remove the old bullet-hit loop from `UpdateEnemies`.
- Preserve one-hit-per-bullet/no penetration. Add a bounded lifetime/range (e.g. 4 seconds) to release over-wall bullets that never strike; release on leaving map bounds.
- Reserve five slots before firing shotgun; reserve one for other shots. No allocation: only successful full reservation consumes ammo/cooldown.

Use a head collider for headshot picking as well as projectile collision. Do not reintroduce projected ellipses or pixel offsets in final combat.

Preserve same-frame contact-before-projectile-damage ordering explicitly. Split combat into `UpdateWeaponInput` (selection/heal/fire/reservation), enemy movement/separation/contact update, then `ResolveProjectiles` (integrate complete segment, earliest wall/enemy impact, ApplyDamage), then effects. This corrects wall/target ordering without silently allowing a lethal bullet to cancel contact already due that frame. ApplyDamage's new stagger begins affecting the next enemy movement tick. Camera/input still use one snapshot; loss still precedes exit progression.

### 3.6 Renderer

Use `BeginMode3D/EndMode3D` for the world and the depth buffer for opaque geometry. Do not translate Y-sort biases into world Z offsets.

Pass order:

1. Clear target color/depth.
2. BeginMode3D with immutable frame camera.
3. Draw opaque cached map and props.
4. Draw opaque geometric actors, held weapons, pickups, exit assembly.
5. Draw alpha-tested temporary billboards/fence panels if any remain.
6. Draw ground contact decals with small normal offset.
7. Draw blended debris fades/particles, sorted far-to-near by camera depth, depth-test on, depth-write off.
8. Draw additive effects with depth test on and restore blend/depth-write state.
9. EndMode3D; present target with tonemap only, never old radial lighting.
10. Draw HUD/crosshair/menu/end-state scrim.

Opaque order must not affect correctness. Transparent order still matters, but a single ground-Y key does not work in 3D. Use a bounded transient `TransparentItem` list, reserve capacity once, clear per frame; camera-forward depth sorts far-to-near. Restore all rlgl state after custom draws.

Map mesh chunks: 16x16 cells, separate floor/wall opaque surfaces, omit internal shared wall faces, preserve top surfaces. Construct once per level/R rebuild. A chunk is safely below unsigned-short index limits when vertices duplicate per face. If combining chunks, enforce <=65535 vertices per Raylib5 indexed mesh. Use checked `MemAlloc`/`MemFree`, `UploadMesh`, valid normals/UVs/colors, correct winding. Cull offscreen chunks after correctness, never rebuild meshes in a render loop.

Small prop assemblies can initially draw reusable cube/cylinder meshes. Optimize by batching static props into chunk meshes if measured draw calls exceed budget. Do not generate mesh assets per enemy/frame.

### 3.7 Lighting

Forward world-space shader, GLSL330:

- Inputs: vertex position, normal, UV, vertex color; uniforms matching Raylib mesh conventions (`mvp`, `matModel`, `matNormal`, `colDiffuse`, `texture0`).
- `worldPosition = matModel * vertexPosition`; world normal from inverse-transpose `matNormal`.
- Ambient/hemisphere plus one directional key and max 16 point lights.
- Point light position is Vector3, radius world units, color/intensity float.
- Reserve one slot for player torch; choose other lights by world-space distance to camera target/player, deterministic tie-break.
- Initial point-light attenuation can be `max(0,1-distance/radius)^2`; clamp total intensity/tonemap.
- Use neutral albedo instead of painting fake light/shadow into every face.
- Display/weapon accents are emissive; emission parameter per draw or material. Dynamic uniform changes must not leak into unrelated meshes.
- No mandatory shadow-map/PBR/SSAO/bloom work. Start with contact shadows and directional shading. True shadow maps are a later optional feature with separate budget.
- Room lights at useful real heights; original radius/intensity/palette preserved approximately.
- Do not run `assets/shaders/lighting.fs` on an already-lit 3D scene.
- Missing/failed shaders must still render readable default Raylib material colors.
- Validate required uniform locations and compare to the default shader id using appropriate Raylib/rlgl APIs. A nonzero id alone is not proof of custom compilation.

### 3.8 Asset And Model Contract

Required final asset catalog:

- Player: blue tactical armor, orange visor; geometric head/torso/paired arms/paired legs.
- Enemy: same proportional vocabulary, crimson armor/amber accents.
- Four distinguishable held/pickup weapon models: Y-fork slingshot, double-barrel/pump silhouette shotgun, scoped long marksman rifle, multi-barrel gatling.
- Six existing prop types: partition curtain, grid-aligned fence, parts table, locker, vending machine, screen terminal.
- Enemy death pieces reuse EXACT live part geometry, pivot, material, and scale.
- Cyan exit beacon assembly.

Procedural models are the mandatory fallback and recommended first complete implementation. Use cached low-poly cubes/cylinders/spheres, local part transforms, a root yaw, and time-driven walk/idle/recoil/stagger poses. This provides real 3D and detachable geometry without an external modeling blocker.

Model axes: +Y up, units meters/tile units, root at feet center, local +Z character forward. Set root yaw so facing vector `(dx,dz)` matches geometry. Local weapon grip/muzzle sockets and head collider are authored alongside model dimensions, not guessed from screen position.

Define GPU-independent `ActorDefinition`, `WeaponDefinition`, and `ActorPose` contracts before M3. Pose evaluation returns root/part transforms and world-space sockets/collider centers; rendering, picking, projectile collision, and death snapshots all consume that same CPU pose. Evaluate pose from current movement/yaw/stagger state before each query; recalculate after enemy movement for impact resolution. A leaning animated helmet cannot use an unrelated fixed world head center. M4 meshes conform to these predeclared dimensions/sockets rather than defining them for the first time.

Target initial proportions: actor height 1.20, torso height ~0.45, helmet radius ~0.17, shoulder width ~0.40, arms/legs narrow. Render a mannequin next to a unit tile and screenshot before mass replacement. Tune final values together with hit volumes.

For imported assets later, prefer self-contained static GLB. Bundled Raylib5 source supports both GLB models and GLTF animations, but import correctness requires a smoke test. Blender is optional and must not block this agent completing procedural geometry. Verify transforms, scale, normals, material textures, animation clips, and sockets in a one-model test before replacing the fallback.

Raylib `Model` is shallow-copyable and owns resource pointers: never unload a copied shared Model twice. `UpdateModelAnimation` mutates model mesh buffers; do not animate a shared skinned model once and assume per-enemy poses are independent. For this port use procedural articulation; imported per-instance skinning/resource strategy is a separate explicit task if chosen.

Keep shader ownership separate from model/material ownership. One render-resource owner initializes once after window creation, rebuilds level mesh cache, and destroys exactly once before `CloseWindow`. Game simulation never owns transient GPU allocations.

Raylib5 ownership details matter: `UnloadMaterial` unloads nondefault shaders/textures, whereas `UnloadModel` frees its material-map arrays without freeing those shared shader/texture resources. Do not call `UnloadMaterial` on a material borrowing shared resources. Explicitly assign owners for meshes, material-map arrays, textures, and shaders; copied draw handles borrow all of them. Destroy borrowed map arrays safely without unloading shared assets, then unload owner-held textures/shaders once. Verify actual bundled source when implementing cleanup.

### `src/World3D.hpp`

```cpp
#pragma once
#include "raylib.h"
#include <cmath>

namespace World3D
{
constexpr float kPixelsPerWorldUnit = 45.254834f;
constexpr float kVerticalPixelsPerUnit = 39.191836f;
constexpr float kInitialWallHeight = 0.816497f;

inline Vector3 FromGround(Vector2 p, float height = 0.0f)
{
    return Vector3{p.x, height, p.y};
}

inline Vector2 ToGround(Vector3 p)
{
    return Vector2{p.x, p.z};
}

inline Vector2 CellCenter(int x, int gridY)
{
    return Vector2{static_cast<float>(x) + 0.5f,
                   static_cast<float>(gridY) + 0.5f};
}

inline BoundingBox WallBox(int x, int gridY, float height = kInitialWallHeight)
{
    return BoundingBox{
        Vector3{static_cast<float>(x), 0.0f, static_cast<float>(gridY)},
        Vector3{static_cast<float>(x + 1), height, static_cast<float>(gridY + 1)}
    };
}

inline bool IntersectGround(Ray ray, Vector3& point)
{
    if (std::fabs(ray.direction.y) < 1e-6f) return false;
    const float t = -ray.position.y / ray.direction.y;
    if (t < 0.0f || !std::isfinite(t)) return false;
    point = Vector3{
        ray.position.x + t * ray.direction.x,
        0.0f,
        ray.position.z + t * ray.direction.z
    };
    return std::isfinite(point.x) && std::isfinite(point.z);
}
}
```

### Required Renderer Ownership/API

Create `src/SceneRenderer3D.hpp/.cpp`, `src/ModelAssets.hpp/.cpp`, and `src/RenderResources3D.hpp/.cpp`:

### Math Tests

The assert-based test executable may use the following complete seed test; expand with the cases above.

```cpp
#include "World3D.hpp"
#include <cassert>
#include <cmath>

static bool Near(float a, float b) { return std::fabs(a - b) < 1e-5f; }

int main()
{
    const Vector2 center = World3D::CellCenter(2, 3);
    assert(Near(center.x, 2.5f) && Near(center.y, 3.5f));
    const Vector3 world = World3D::FromGround(center, 1.0f);
    assert(Near(world.x, 2.5f) && Near(world.y, 1.0f) && Near(world.z, 3.5f));
    const Vector2 back = World3D::ToGround(world);
    assert(Near(back.x, center.x) && Near(back.y, center.y));
    Vector3 hit{};
    assert(World3D::IntersectGround(
        Ray{Vector3{2.0f, 5.0f, 3.0f}, Vector3{0.0f, -1.0f, 0.0f}}, hit));
    assert(Near(hit.x, 2.0f) && Near(hit.y, 0.0f) && Near(hit.z, 3.0f));
    assert(!World3D::IntersectGround(
        Ray{Vector3{0.0f, 1.0f, 0.0f}, Vector3{1.0f, 0.0f, 0.0f}}, hit));
    assert(!World3D::IntersectGround(
        Ray{Vector3{0.0f, 1.0f, 0.0f}, Vector3{0.0f, 1.0f, 0.0f}}, hit));
    return 0;
}
```

CTest Release builds may define NDEBUG: use an always-active CHECK macro/explicit error returns or undefine NDEBUG for test targets. Do not accidentally compile every assert out and report success.
